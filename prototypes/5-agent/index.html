Samaltak — agent design proposals

Five ways to put a coding agent (Codex 6.1 Sol, code-mode + show-object) into the system. Same conversation in each: rank UI-Widgets classes by method count, show the top five. Plan: docs/agent.md.

✓Chosen: ⌘J opens an Agent window

Proposal 5's context binding with proposal 1's conversation window.

⌘J in any tool; self, thisContext, temps and the selection come along.

1Agent Workspace

One more classic tool: transcript with inline cells and objects, prompt below.

Least new concepts; the object table is implicit.

2Live Notebook

Every code-mode call is an editable cell; the user's own cells feed the agent.

Shared medium for user and agent; the transcript gets long.

3Agent Browser

Browser panes: conversations, transcript, the object table and an Inspector on it.

Objects first-class; dense, needs a big window.

4Desktop Agent

Ask from the top bar; show-object opens real tools on the desk, tagged and linked.

Reuses every tool; the desk fills up.

5Agent in every tool

⌘J in any Workspace, Inspector, Debugger or Browser, with the tool's context bound.

Deepest integration; conversations scattered across tools.
