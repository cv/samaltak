# Samaltak UI stack spec

How the image draws, composites, and handles input. Everything here is Smalltalk except the platform primitives (`vm/platform/README.md`). Visual reference: the Blue Book + pi-orb prototype (`prototypes/1-classic/`, especially `themes/blue-book.css`, `types/pi-orb.css`, `debugger.css`, `profiler.css`, and `prototypes/screenshots/bb-piorb.png`). The real system should look like that prototype, only better.

**Layering** (enforced by the image builder, which rejects violations with file:line): a package may reference globals of packages on its own layer, the layer directly below, and layer 0 (Kernel, System, Compiler). Exceptions, all declared in `src/packages.txt`:

- Graphics-Canvas' drawing vocabulary — `Canvas`, `Color`, `Font`, `Form`, `FragmentShader` (`Point`, `Rectangle` are Kernel) — may be used from layer 3 up (`export Graphics-Canvas 3 Canvas Color Font Form FragmentShader`): widgets and tools draw.
- Test packages may list the packages their fixtures need (`Tests-Tools 5 uses UI-Windows Graphics-Canvas`).

Tools (5) never name `Window`, `World` or `UIWindows`: UI-Widgets' `Desktop` forwards to them (`Desktop current` is the World, `Desktop newWindow` a Window, plus the World's hooks and the startup action). Lower layers reach higher ones only late-bound (`Smalltalk at: #Tools ifAbsent: […]`).

## Graphics-GPU (layer 1)

Thin, WebGPU-shaped objects over the `gpu*` primitives, each holding a platform handle and releasing it when asked: `GPUDevice` (factory for everything below; `GPUDevice default`), `GPUShader`, `GPUPipeline`, `GPUTexture` (width, height, format), `GPUSampler`, `GPUBuffer`, `GPUCommandBuffer` (`beginPassOn:clear:` → `GPURenderPass`, `blit:to:`, `submit` → `GPUFence`), `GPURenderPass` (`pipeline:`, `vertexBuffer:`, `texture:sampler:slot:`, `uniforms:`, `scissor:`, `viewport:`, `draw:from:`, `end`), `GPUFence` (`wait`, `isDone`), `GPUSwapchain` (per window). Handles die with the process; on image startup every GPU object is re-created lazily (they hold their creation parameters).

## Graphics-Canvas (layer 2)

- **Fonts**: `TrueTypeFont` parses a `.ttf` (`cmap` format 4/12, `glyf`/`loca`, `hmtx`, `hhea`, `head`, `OS/2`) in Smalltalk. `Font` = typeface + pixel size + device scale; answers metrics (ascent, descent, line height, advance of a Character, width of a String). `GlyphAtlas` rasterizes glyph outlines (quadratic Béziers, non-zero winding, exact area coverage) into an R8 atlas texture at device resolution, lazily, caching glyphs; atlases for the standard fonts are pre-rasterized in stage 2 and live in the image. `aFont glyphFor: $g` answers a `GlyphForm`: the glyph's coverage as drawn (read back from its atlas page; alpha = coverage). Standard faces: Iosevka Etoile Regular/Bold/Italic (UI, text) and JetBrains Mono Regular/Bold/Italic (code), from `fonts/`.
- **Canvas**: the only drawing API widgets see. Coordinates in points (float). `fillRect:color:`, `strokeRect:color:width:`, `line:to:color:width:` (axis-aligned and diagonal), `drawString:at:font:color:` (baseline-free: `at:` is the top-left of the line box), `drawString:in:font:color:align:`, `image:in:` (a `Form`: Bitmap + extent, uploaded as a texture on demand), `pattern:in:` (procedural fills: `#halftone`, `#stripes` — computed in the fragment shader in device pixels), `clip:during:`, `translateBy:during:`, `alpha:during:`, `measure:font:`. A Canvas records into a **DisplayList**: a ByteArray of vertex data (pos float2, uv float2, color rgba8, mode/extra) plus a short list of batches (texture, scissor, first, count, and a move in whole device pixels the vertex shader adds). Once frozen, a DisplayList is never mutated. Retained drawing: `record: aBlock` answers a **DisplaySegment** of what aBlock drew; `replay: aSegment` on a later Canvas draws it again (copying its vertices, moved by whole device pixels) when scale, opacity and the clip relative to the origin match, else answers false; `drawFresh:` refuses all replays inside; `noteVolatile` marks what shows values computed while drawing.
- **Renderer**: owns the pipelines (MSL source in Smalltalk), uploads a DisplayList into a vertex buffer and encodes it into a render pass. One uber-shader with modes: solid, glyph (R8 coverage), image (RGBA), halftone, stripes.
- **FragmentShader**: an MSL fragment function (after a prelude: `ShaderIn` with uv and size) rendered over a texture of its own; `imageExtent:source:uniforms:` answers a **ShaderImage**, one immutable frame that `image:in:` draws like a Form: rendered when the Renderer first draws it (in a command buffer submitted before the frame's), again only when the texture lost its contents (new session). New source builds a new pipeline; source that does not compile keeps the old one and goes to `Renderer reportShaderError:`.
- **Color**: `Color r:g:b:a:` (floats), named colors, `alpha:`, `mixed:with:`; packs to rgba8.
- **Form**: Bitmap (32-bit RGBA) + width/height; `at:put:`, `fill:`; dirty tracking for texture upload; `pixelComponentNames` / `pixelComponentsAt:` (r g b a; a GlyphForm's coverage).
- **PNGWriter**: encodes a Form or RGBA bytes as PNG in Smalltalk (stored-deflate blocks, CRC-32, Adler-32).

## UI-Windows (layer 3)

- **World**: the desktop (halftone pattern), the window list (z-order), focus, the top bar, the pointer, menus and toasts as overlay layers. `World current`.
- **Compositor**: a Process at priority 70 woken by the platform's vsync semaphore (`vsyncSemaphore:`), presenting at most 60 Hz (every second refresh on a 120 Hz display: presenting faster makes the Metal swapchain acquire block the single VM thread). Each frame: for every Layer whose content changed, render its latest frozen DisplayList into the layer's texture; then composite all layers onto the swapchain (and, when recording, into an offscreen target that is downsampled and read back), apply layer transforms (offset, scale, opacity), draw hard shadows; record a **FrameRecord** (start/end µs, per-Process CPU deltas from `Process>>cpuTime`, draw/raster/GPU times, GC counts/µs from `vmStats`). The compositor never waits for a window's Process: a busy window keeps its last frame and stays draggable.
- **Layer**: texture, bounds, transform, opacity, `latestDisplayList` (set atomically by the owning Process), dirty flag.
- **Window**: title, bounds, content (a Widget tree), its own **Process** (priority 40, named after the window) running an event loop over a `SharedQueue` of items that run themselves there (`deliverTo:`: blocks, WindowTimers, input events); redraws its content into a fresh Canvas when invalidated and publishes the frozen DisplayList to its Layer. Drawing is retained: each View replays its last drawing (`drawRetainedOn:`) unless it changed since; `invalidate` redraws a view and everything in it, a moved view is replayed moved, `Window>>invalidate` redraws everything. A view whose drawing reads other objects' state must invalidate when that state changes (`View verifyDrawing: true` compares every replay with drawing anew). Title bar (Blue Book: stripes when focused, title tab), close/collapse boxes, drag, resize from edges/corner, focus. `Window>>busy` indicator when its Process is computing (e.g. the Mandelbrot). Window open/close and focus changes animate.
- **InputDispatcher**: a Process at priority 60 that reads platform events (the input semaphore), tracks the pointer and modifiers, routes each event to the right Window's queue (pointer → window under the pointer or the one with capture; keys → focused window), and handles window-manager gestures (title-bar drag, resize, raise) itself so they stay live while a window's Process is busy. Remote input arrives through the same path (`injectEvent:`). Each platform event Array is decoded once (`UIEvent fromPlatform:`, event types named `UIEvent evMouseMove` … after the platform layer's PF_EV_ constants) into an input event or a host window event (HostResizeEvent, QuitEvent, FocusLostEvent, ScaleChangedEvent, PointerLeftEvent, ExposeEvent) that dispatches itself (`dispatchTo:`); drags and resizes are DragGesture / ResizeGesture objects.
- **Animation**: `Animation` tweens a property (number, point, rectangle, color: `interpolateTo:at:`; other objects jump at the end) with a duration and easing (`#easeOutCubic`, `#easeInOutQuad`, spring) on the compositor clock. Layer properties (offset, scale, opacity) are animated by the compositor itself — smooth even when the window's Process is busy. Widget animations (selection bars gliding between rows, the debugger's pc highlight moving between expressions, flame-graph zooms, tab cross-fades, toasts) re-render the window each frame while running. Durations 90–220 ms; subtle, never bouncy-cute. The compositor clock is `Animation now`: real time divided by `Animation timeScale` (`Animation timeScale: 10` is slow motion for every animation, toasts, tooltip delay, caret blink and the remote pointer's travel; World menu 'Slow motion', top bar tag '10× SLOW'; Tools use `Desktop animationTimeScale:`), continuous when the scale changes. Timers that are animation time use `Widget>>afterAnimationTime:do:`; Delays, refresh timers and timeouts stay real.
- **Snapshots**: an image saved while its World runs (World menu › Save image, `Tools saveImage`) resumes that World when started again with a display (`UIWindows startUp:` → `World>>resumeHidden:`): the windows (bounds, z-order, focus, content) and their Processes are as saved, so a Debugger still holds its suspended Process. The host window re-opens at the saved size (hidden per the new command line), GPU objects re-create their handles, a new Compositor and InputDispatcher start (fresh external semaphores), layers render again; layer and window animations jump to their end, toasts are dropped, Delays are rebased (`Delay shutDown`/`startUp`). The snapshotting Process continues after the snapshot; headless, the saved World is abandoned and the command line runs as in a fresh image.
- **Scheduling rule**: Smalltalk code that touches a window's widgets runs in that window's Process (`window do: [ ... ]` enqueues a block).

## Live changes

Accepted code takes effect on the running screen. `SystemChanges` (Kernel-Classes) announces every method added, changed or removed (Behavior) and every class defined (ClassBuilder) to subscribers, in subscription order (= load order, lower layers first), in the changing Process: `SystemChanges subscribe: #key do: [:change | ...]`, `change affects: aClass` (aClass or a subclass, either side), `SystemChanges silentlyDuring:`. Subscribers:

- `Color`: a change to Color drops the named-color palette (rebuilt on use).
- `Renderer`: a change to Renderer (its MSL source is `Renderer class>>shaderSource`) makes every Renderer build its pipeline again before its next render; if the source does not compile the old pipeline stays and `Renderer shaderErrorHandler:` gets the error (UI-Windows: Transcript + a toast with the first Metal message). `pipelineVersion` counts rebuilds; the Compositor then renders every cached layer again.
- `Font`: a change to Font, GlyphRasterizer or TrueTypeFont resets the GlyphAtlas and every Font's glyphs; they are rasterized again on first use (~150 ms for the default desktop). GlyphAtlas allocation is serialized (window Processes rasterize concurrently).
- `UIWindows`: a change to a View subclass or to a class in Graphics-GPU, Graphics-Canvas, UI-Windows or UI-Widgets restyles `World current`: every window and overlay redraws its content without replays and its chrome; the top bar drops its fonts.
- `Theme`: a change to Theme or Color makes `Theme current` run its definition again (`refresh`: colors and metrics, fonts kept), publish its colors as Color's named colors (the chrome draws with `Color ultramarine`), and restyle the World.

The desk is `World>>drawDeskOn:`, drawn by the compositor every frame.

## Window ↔ content contract (UI-Windows defines, UI-Widgets implements)

UI-Windows (layer 3) defines the abstract classes; `Widget` (layer 4) subclasses `View`.

- **Events** (UI-Windows): `PointerEvent` (`type` #down #up #move #wheel #enter #leave, `position` (Point, local to the receiver when delivered), `globalPosition`, `button` 1 left / 2 right (also ctrl-click) / 3 middle, `clickCount`, `delta` for wheel, `modifiers`), `KeyEvent` (`type` #down #up, `key`: a Symbol for named keys — #left #right #up #down #return #enter #backspace #delete #escape #tab #home #end #pageUp #pageDown #space — or a lowercase Character for printable keys, `modifiers`), `TextEvent` (`string`). Modifiers answer `shift` `control` `option` `command` and `commandKey` (⌘ on macOS). Events come from the platform's 8-slot Arrays, real or injected, through the same path.
- **View** (UI-Windows): what a Window's content is. `owner`, `window`, `bounds` (in owner coordinates) / `extent`, `layout` hook called after resize, `drawOn: aCanvas` (local coordinates: 0@0 is the view's top-left; the window translates and clips), `children` (default: none), hit testing `viewAt: aPoint`, `handlePointer: evt` / `handleKey: evt` / `handleText: evt` answering true when handled (default: bubble to owner), `wantsKeyboardFocus`, `focusGained` / `focusLost`, `cursorAt: aPoint` (#arrow #ibeam #hand #resizeEW #resizeNS #resizeNWSE #move), `invalidate` (asks its window to redraw), `contextMenuAt: aPoint` (answer a Menu model or nil), and the remote-control protocol (`remoteRole` `remoteLabel` `remoteState` `remoteName` `remoteChildren`, defaults derived from class and children).
- **Window**: `Window new title: aString; content: aView; bounds: aRectangle; open` (creates its Layer and its Process, priority 40, named after the title), `do: aBlock` (run in the window's Process), `sync: aBlock` (run there and answer its value; an Error in aBlock is signaled again in the caller, same exception with its original stack: `Exception>>freeze` / `resignal`), `invalidate`, `close`, `focus`, `isFocused`, `busy:` (shown in the title bar while true; the window manager stays live), `process`, `world`, `title:`, `keyboardFocus:` (a View), `requestAnimationFrames: aBlockOrAnimation` (redraw every compositor frame while it runs), and `Window>>openNotifier…`-style helpers left to Tools. Its Process loop: take the next event from its SharedQueue, deliver it to the content (with hit testing, pointer capture between down and up, keyboard focus), and redraw when invalid.
- **World**: `World current` — `windows` (front to back), `openMenu: aMenuModel at: aPoint` (overlay layer; the Menu view is a Widget, the World only hosts it), `toast: aString`, `activeWindow`, `bounds`, `topBar`.
- **Animation**: `Animation from: a to: b duration: ms easing: #easeOutCubic do: [:value | …]` runs on the compositor clock; started by a View via `self window animate: anAnimation`; Layer properties (`offset`, `scale`, `opacity`) animate in the compositor without involving the window's Process.

## UI-Widgets (layer 4)

`Widget` (bounds, owner, children, layout, `drawOn:`, event handlers `mouseDown:`/`mouseMove:`/`mouseUp:`/`keyDown:`/`textInput:`/`wheel:`, focus, `invalidate`, cursor, tooltip, `contextMenu`) and: Label, Button (Blue Book: 1px frame, inverted when pressed or default), ToggleGroup/Tabs, ListView (rows with optional icon/gutter cell/right-aligned muted text, selection that glides, keyboard navigation, scrolling, double-click, context menu), TextEditor (multi-line, caret, selection, mouse drag/double-click word, keyboard incl. word/line movement, undo, clipboard, scrolling, syntax highlighting via the Compiler's Scanner, marks: result/error/pc highlight ranges, do it/print it/inspect it/accept hooks; a facade over TextBuffer (text, line index, word boundaries, change listeners), TextLayout (rows and wrapping, column ↔ x, caret/selection rectangles, scroll offset), TextHighlighter (Scanner tokens, incremental rescans, styled runs) and TextUndoHistory (grouped typing)), Splitter, ScrollPane, PaneHeader (tiny tracked caps label + muted right text), StatusBar, Menu (popup, keyboard navigable, fades in), Toast, Notifier frame, ShaderView (a FragmentShader's picture: `shaderSource`, `uniforms` as float4 rows, `renderScale`; a new frame at each drawing). Layout: simple rows/columns with fixed/flexible sizes; no constraint solver.

**Theme** (`Theme current`, Blue Book): black on white; 1px black rules; hard 2px offset shadow on the focused window; halftone desk; ultramarine `#1b3a8c` as the only accent; selection by inversion in focused lists, a 1px box otherwise; fonts: UI Iosevka Etoile 13.5px, headers tracked capitals 10.5px bold, code JetBrains Mono 13px/20px.

**Remote-control hooks**: every Widget answers `remoteRole` (#window #list #item #editor #button #tab #menu #canvas #status …), `remoteLabel`, `remoteState` (Array of words like `selected` `focused` `dirty`), `remoteName` (stable slug used to build refs like `@w3.packages.kernel-numbers`), `remoteChildren`, and `remoteAction: #click|#select|…` where needed. The snapshot is computed in Smalltalk from the live widget tree.

## Demos (layer 3)

`DemoView` and subclasses (a click counter, a busy Process, an animation) and `CanvasDemo` (a Blue Book mock desktop drawn with the Canvas, `CanvasDemo run` / `writePNG:` / `benchmark`). Without the Tools, the demo windows are the startup action.

## Tools (layer 5)

System Browser, Workspace, Transcript, Inspector, Process Browser, Mandelbrot, Terminal, World menu, Notifier, Debugger, Breakpoints, Profiler, control service. Behavior and look follow the prototype (see `prototypes/1-classic/*.js` for the interactions and the default workspace text), with everything real: real classes and methods, real processes, real stepping, real samples. The Inspector shows a Form's pixels magnified (`PixelView`, ref `pixels`: integer zoom that fits, grid from zoom 6, wheel or + − 0; the hovered pixel's value in `pixel-status`; state `zoom=17 size=12x20 hover=6,12 value=252`): `(Font code glyphFor: $g) inspect`, then `samaltak-ctl hover @wN.pixels --at 6,12`.

**Terminal** (World menu "Terminal", `Tools openTerminal`, `Tools open: #terminal`): a login shell (`$SHELL -l`) in the repository holding the image's `src/`, on a pseudo-terminal (`PseudoTerminal`, System-Files, over the `pty*` primitives). `TerminalParser` interprets the program's output (UTF-8, C0, ESC, CSI incl. scroll regions, insert/delete, SGR 16/256/truecolor, DEC modes: alternate screen 47/1047/1049, application cursor keys, autowrap, cursor visibility, bracketed paste; OSC 0/2 title; device reports) into a `TerminalScreen` (rows of `TerminalLine`: a character and a packed attribute per cell; 5000 lines of scrollback). `TerminalView` draws it in JetBrains Mono (ANSI colors tuned to the Blue Book; box drawing and block elements as rectangles), one retained segment per row, the cursor in the overlay (Theme caret blink); keys are encoded as xterm does (⌥ = meta, ⌘C/⌘V/⌘A/⌘K stay with the GUI). An I/O Process ('Terminal pty') reads in 16 KB slices into a queue (it stops reading above 1 MB) and the window's Process interprets it at once, then once per compositor frame (≤ 10 ms), so heavy output redraws at most once per frame. Remote: `@wN.terminal`, role `terminal`, state `rows= cols= cursor=r,c title="…" alt-screen exited=n`, the shown rows as text.
