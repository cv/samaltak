# Certificates

`System-TLS` (layer 0) holds what TLS rests on besides the cryptography (docs/crypto.md): DER, X.509 certificates, trust anchors and chain validation, for the TLS 1.3 client in Smalltalk where the VM has no OpenSSL (UEFI, docs/uefi.md). Errors are `TLSError` (an Error) whose text says what failed. Tests: `Tests-TLS`.

## API

- **DER** (`Asn1Der`, X.690): `(Asn1Der on: bytes) readSequence` answers a reader over the sequence's contents; `readSet`, `readExplicit: n` and `readOptionalExplicit: n` likewise. Values: `readInteger`, `readBoolean`, `readNull`, `readOid` ('1.2.840.10045.4.3.2'), `readOctetString`, `readBitString` (whole bytes), `readNamedBits` (bit n of the string is `1 bitShift: n`), `readString` (UTF8, Printable, IA5, Teletex as Latin-1, BMP, Universal), `readTime` (UTCTime or GeneralizedTime → seconds since 1970 UTC); `readElementBytes` (an element as encoded), `peekTag`, `nextIs:`, `skip`, `atEnd`, `expectEnd`.
- **Certificates** (`X509Certificate`, RFC 5280): `fromDer: bytes`, `allFromPem: text`; `version`, `serialNumber`, `subject` and `issuer` (`X509Name`: `commonName`, `attributes`, printed 'CN=..., O=..., C=..'; equal when their DER is), `notBefore`, `notAfter` (seconds since 1970 UTC), `publicKey` (an `RsaPublicKey` or `EcPublicKey`; nil for another kind, e.g. a P-521 root), `signatureAlgorithm` (#sha256WithRSAEncryption, #sha384WithRSAEncryption, #sha512WithRSAEncryption, #rsassaPss, #ecdsaWithSHA256, #ecdsaWithSHA384, #ecdsaWithSHA512, else #unsupported); extensions: `isCA`, `pathLength` (basicConstraints), `keyUsage` and `hasKeyUsage: #keyCertSign`, `extKeyUsage` and `allowsServerAuth`, `dnsNames` and `ipAddresses` (subjectAltName), `subjectKeyId`, `authorityKeyId`, `extensions` (OID → {critical. value}), `unhandledCriticalExtensions`. `isSignedBy: issuerCertificate`, `verifySignatureWith: aKey`, `matchesHostName: host`, `isValidAt: seconds`.
- **Trust anchors** (`TrustStore`): `TrustStore default`, the roots of `TrustStoreRoots`, parsed on first use (120 roots in 14 ms); `TrustStore new add: certificateOrDer` (a test's own CA); `includes:`, `issuersOf: cert`, `certificates`.
- **Validation** (`CertificateValidator`): `CertificateValidator new trustStore: ts; validate: chain host: name at: seconds` (`validate:host:` now) answers the path, leaf to anchor, or signals TLSError with the reason, e.g. 'certificate CN=*.nvidia.com expired at 2027-02-18 23:59:59 UTC'. `chain` is what the server sent, leaf first, X509Certificates or DERs.

## How

`Asn1Der` is strict DER, bounds-checked: lengths definite, minimal and within the enclosing element, single-byte tags, minimal INTEGERs, BOOLEANs 00 or FF, BIT STRINGs without stray unused bits, times with seconds and Z, constructed elements at most 32 deep. `X509Certificate` keeps the signed bytes as received and parses the signature algorithm's parameters (RSASSA-PSS: SHA-2 hash, MGF1 with the same hash, its salt length, trailer 1) and the extensions it knows; certificate policies, policy constraints and inhibitAnyPolicy count as understood (any policy is accepted, as browsers do), any other critical extension makes validation fail.

The validator first checks the leaf: the host (subjectAltName only, no common name fallback; RFC 6125: ASCII case ignored, a trailing dot ignored, a wildcard only as the whole leftmost label and matching exactly one label, never in an IP address; IPv4 hosts against iPAddress names), its validity, digitalSignature if it has keyUsage, serverAuth if it has extKeyUsage. Then it builds a path depth-first: from each certificate, first to an anchor whose subject is its issuer and whose key verifies its signature, so that an anchor ends the path even where the server sent a cross-signed copy of it (inference-api.nvidia.com sends Amazon Root CA 1 signed by Starfield Services G2), else on through each certificate the server sent with that subject, in any order, each once, backtracking on failure. Every issuer must verify the signature, be within its validity, be a CA (an anchor without extensions, X.509 v1, counts as one), allow keyCertSign if it has keyUsage and serverAuth if it has extKeyUsage, and have no more CAs below it than its pathLenConstraint. Paths have at most 8 certificates. When all fail, the reason is that of the attempt that got furthest. Not checked: revocation (CRLs, OCSP), name constraints (a CA with critical ones fails), certificate transparency.

`TrustStoreRoots` is generated by `tools/ca-bundle-to-smalltalk.py [bundle]` from a PEM CA bundle (by default `/etc/ssl/certs/ca-certificates.crt`, Mozilla's roots as Debian and Ubuntu ship them): each root's name and DER in Base64, sorted, one literal Array; the script fails if Amazon Root CA 1 or Starfield Services Root Certificate Authority - G2 is missing. Regenerate it when the roots change, then `TrustStore resetDefault` in a running image.

## Tests

`Tests-TLS`: `Asn1DerTest` (what DER forbids), `X509CertificateTest` (fields of real and generated certificates, every root parses, host names), `TrustStoreTest`, `CertificateValidatorTest`: real chains captured once (`TLSRealChains`: inference-api.nvidia.com's, RSA, through the cross-signed Amazon Root CA 1, also validated with only Starfield G2 trusted; letsencrypt.org's, ECDSA P-256 and P-384 through Root YE cross-signed by ISRG Root X2) and generated ones (`TLSTestCertificates`, by `tools/tls-test-certificates.py`, python3-cryptography: an ECDSA and an RSA hierarchy with sha512/384WithRSAEncryption and RSASSA-PSS, a cross-signed root, and leaves that break one rule each: wrong host, expired, not yet valid, wrong issuer, bad signature, a non-CA issuer, a path length exceeded, an issuer without keyCertSign, a client-only leaf, an unknown critical extension). They run on UEFI too (`make test-uefi`).

## Performance

`--jit opt` hosted on arm64 (an NVIDIA GB10, Linux): validating inference-api.nvidia.com's chain (two RSA-2048 verifications, SHA-256 of the signed parts, the host) 0.55 ms; letsencrypt.org's (ECDSA P-256 and two P-384) 9 ms; parsing the 120 roots 14 ms.
